## Browser evidence and measurement scope

The browser checks ran in local headless Chrome against the Release app at `127.0.0.1:5194`, in a disposable browser profile. `artifacts/mobile-audit/phase06-units.json` covers Unit 01–36: each opened, rendered a single visible section, had a reachable assessment entry, navigated to the next section and had no duplicate IDs or JavaScript exceptions. `artifacts/mobile-audit/mobile-plan.json` contains 144 page states (9 routes × 4 widths × VI/EN × light/dark), with one `h1` and main landmark per tested page and no horizontal page overflow. `docs/unit-coverage-matrix.md` lists every discovered Unit and its actual section/exercise families.

Actual screenshots are under `artifacts/mobile-audit/`: `mobile-home-*`, `mobile-settings-*`, `mobile-vocabulary-*`, `mobile-flashcards-*` and `mobile-unit-vocabulary-*`. Unit vocabulary screenshots cover all 16 width/language/theme combinations. Home, vocabulary, flashcard and Unit vocabulary screenshots at 320 px were visually inspected. These are **after** screenshots. No matching before screenshots were captured in this run, so no before/after image diff is claimed.

The browser harness recorded local boot-to-marker median 1870 ms for the 144 states. One Help desktop EN run recorded CLS 0.277; a separate reproduction recorded 0.00007, so the cause remains unconfirmed. These are local synthetic observations, not field Core Web Vitals. FPS, INP, a complete contrast audit, screen-reader behavior, text scaling and physical-device testing were not measured. The earlier Phase 06 report covers prior light-theme token contrast samples, not a full audit.
